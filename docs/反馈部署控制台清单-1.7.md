# 反馈部署控制台清单（1.7，内部操作清单）

本清单只写 secret / var 的名字与控制台动作，不写真值。
部署前逐项打勾，缺一项不算部署完成。

## 1. 新建 Worker 与数据库

- [ ] 控制台新建 Worker，名称为 lyric-feedback。
- [ ] 控制台新建 D1 数据库，名称为 feedback_db。
- [ ] 把反馈 Worker 的 schema 应用到 feedback_db。
- [ ] 确认 Worker 已绑定 feedback_db。

## 2. 自定义域名

- [ ] 控制台为 lyric-feedback 绑定自定义域名 feedback.ckaylechou.de5.net。
- [ ] 注意：API 绑域名曾被 405 拒绝，本项走控制台，不走 API。
- [ ] 绑定后确认该域名可以访问。

## 3. workers.dev 开关

- [ ] lyric-feedback 的 workers.dev 开关保持开。
- [ ] 原因：中转上游走 workers.dev 地址。
- [ ] 绝不把中转上游改成自定义域名。

## 4. Secret 填值（控制台填，只写名字）

- [ ] GH_TOKEN：用户在 GitHub 新建，拿到后在控制台填入。
- [ ] ADMIN_KEY：用户自定，拿到后在控制台填入。
- [ ] TG_BOT_TOKEN：从现有发版通知 secret 复制填入。
- [ ] 不新建 bot。
- [ ] 勿动现有 bot @jkmuse_bot。

## 5. Var 填值（控制台填，只写名字）

- [ ] TG_CHAT_ID：填现有接收方。
- [ ] AUTHOR_EMAIL：填作者接收邮箱。
- [ ] GH_OWNER：默认 kaylechou，如无变动按默认填。
- [ ] GH_REPO：默认 propresenter-lyric-tool，如无变动按默认填。

## 6. 中转 /feedback 补丁

- [ ] 把 /feedback 补丁贴入中转。
- [ ] 贴入前按部署时的实际 workers.dev 子域，核对一次上游主机名。
- [ ] 上游主机名不对就先停下改对，不要直接发布。

## 7. 邮件推送（2026-11-04 改 Resend；MailChannels 免费 Workers 路线 2024 年已停，见日志 401）

- [ ] Resend 注册账号（免费档，不用绑卡），建 API Key（Sending access 即可）。
- [ ] Resend 添加域名 ckaylechou.de5.net，按 Resend 给出的记录在 Cloudflare DNS 加验证记录（SPF 若在根域则并进现有值、不另建第二条）。
- [ ] 等 Resend 显示域名已验证（from 须为已验证域名地址，否则发不出）。
- [ ] Cloudflare lyric-feedback 加 secret RESEND_API_KEY（Encrypt 开，值只填控制台、不发聊天）。
- [ ] 加完后测试提交，确认邮件推送能收到。

## 8. 管理视图用法

- [ ] 打开 /admin 页。
- [ ] 在密钥页内输入 ADMIN_KEY。
- [ ] 进入后可查看反馈列表。
- [ ] 可改状态，可写回执。
- [ ] 改完后确认回执已同步到公开镜像 issue。
- [ ] 用完后退出管理视图。

## 9. 作者查看通道自查

- [ ] TG 推送：通知文本以“# feedback（工具反馈信息）”开头。
- [ ] 邮件推送：作者邮箱能收到。
- [ ] 手动管理视图：/admin 页能打开、能改状态。
- [ ] GitHub 通知与 issue 镜像：新反馈能在仓库看到对应 issue。
