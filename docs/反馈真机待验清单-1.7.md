# 反馈真机待验清单（1.7）

本清单只列待验项，不代表已验过。
每一项都要在真实环境实测并留结果，代码层面通过不算通过。

## 1. 端到端提交

- [ ] 帮助面板“反馈”项打开表单，提交成功。
- [ ] 主界面“反馈”按钮打开表单，提交成功。
- [ ] 提交后拿到反馈编号。
- [ ] 用编号在“我的反馈”里查到状态与回执。
- [ ] 查询过程无需登录。

## 2. 截图实拍文件

- [ ] 用真实截图文件走文件选择提交。
- [ ] 用真实截图文件走粘贴提交。
- [ ] 用真实截图文件走拖拽提交。
- [ ] 提交前缩略图预览正常。
- [ ] 单张删除只删该张，不影响其他张。
- [ ] 超 3 张、单张超 5MB、总包超 8MB 时提示重选。
- [ ] PNG、JPEG、WebP 三种格式都实测。

## 3. 直连 / 中转两腿实网

- [ ] 直连腿实网提交成功（反馈 Worker 自定义域名 feedback.ckaylechou.de5.net）。
- [ ] 中转腿实网提交成功（中转 /feedback 代理，上游走 workers.dev 地址）。
- [ ] 两腿分别留实测记录，不要只测一腿就写两腿通过。

## 4. TG / 邮件实收

- [ ] TG 实收：复用现有发版通知 bot 的推送到达。
- [ ] TG 文本开头为“# feedback（工具反馈信息）”。
- [ ] 邮件实收：作者邮箱收到推送。
- [ ] GitHub 通知与 issue 镜像同步到达。

## 5. 管理改状态与回执同步

- [ ] /admin 页密钥页内输入 ADMIN_KEY 后进入。
- [ ] 管理端改状态：待处理、知悉、处理中、已处理、不做，五种都可改。
- [ ] 管理端写回执后，提交者用编号能看到回执。
- [ ] 回执同步到公开镜像 issue，issue 内可见同样状态与回执。

## 6. 已知缺口：原生帮助菜单项后续接线

- [ ] 现状：Electron 原生帮助菜单项尚未接线。
- [ ] 用户向说明里不写该入口，只写已实现的两个入口。
- [ ] 后续需另批动 menu.js 接线，本批不动 menu.js。
- [ ] 接线后补测：原生菜单项打开表单并提交成功。

## 7. 已知限制：对话框内切换语言

- [ ] 现状：对话框内切换语言，需关闭重开才换语。

- [ ] 实测：关闭重开后，语种变为新选语种。
- [ ] 该限制未修好前不要写成“即时换语”。

## 8. 五语对话框实测

- [ ] 简体中文、繁体中文、英语、日语、韩语对话框逐一实测。

- [ ] 任一语种缺文案或串语都算未通过。
